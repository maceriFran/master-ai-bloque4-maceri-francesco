# P3: una interfaz común

Validación realizada el **13 de octubre de 2026**, con el Python del entorno `.venv` existente en Windows PowerShell. Se conserva el trabajo de S0, P1 y P2.

## Implementación

Se siguieron el [código oficial](https://github.com/JavierDomi/master-ia-bloque4/blob/main/s1-llm-apis/P3-una-interfaz-comun/llm_client.py) y el [enunciado de P3](https://github.com/JavierDomi/master-ia-bloque4/blob/main/s1-llm-apis/P3-una-interfaz-comun/README.md), tomando las llamadas de `s1_hola_tres.py` como referencia.

- `responses`: envía el sistema en `instructions`, el prompt en `input` y recupera `output_text`, `usage.input_tokens` y `usage.output_tokens`.
- `messages`: envía `system` separado de los mensajes del usuario, establece el límite obligatorio y concatena únicamente los bloques de tipo `text`.
- `temperatura` se transmite cuando se indica, incluido el valor `0`.
- Se mantienen la estructura, la clase `Respuesta` y las ramas `interactions` y `chat`, añadiendo el límite opcional. Si Chat Completions devuelve `content=null`, se representa como cadena vacía sin alterar los tokens.
- La misma implementación está en `llm_client.py` y `e1/llm_client.py`. No se implementa el reto de streaming.

## Correspondencia de max_tokens

La firma es `responder(sistema, prompt, temperatura=None, max_tokens=None)`.

| Rama | Campo enviado a la API | Si se omite |
| --- | --- | --- |
| Responses | `max_output_tokens` | No se envía límite explícito |
| Messages | `max_tokens` | Se envía `512`, porque el campo es obligatorio |
| Gemini Interactions | `generation_config.max_output_tokens` | No se envía límite explícito |
| Chat Completions de OpenRouter/Ollama | `max_tokens` | No se envía límite explícito |

Fuentes consultadas el 13 de octubre de 2026: [OpenAI Responses, SDK Python](https://developers.openai.com/api/reference/python/resources/responses/methods/create), [Anthropic Messages, SDK Python](https://platform.claude.com/docs/en/api/python/messages/create), [Google Interactions](https://ai.google.dev/api/interactions-api), [parámetros de OpenRouter](https://openrouter.ai/docs/api/reference/parameters) y [compatibilidad de Ollama](https://docs.ollama.com/api/openai-compatibility). También se contrastaron las firmas de los SDK instalados: `openai 3.29.0`, `anthropic 1.13.0` y `google-genai 2.30.1`.

El límite no garantiza una frase completa. En Responses incluye texto visible y razonamiento. La compatibilidad de temperatura y los límites admisibles también dependen del modelo; los errores de la API se propagan al llamador.

## Precios y coste

Se consultaron únicamente las variables `OPENAI_MODEL`, `ANTHROPIC_MODEL` y `GEMINI_MODEL` para identificar los modelos. Precios verificados en el [catálogo público de OpenRouter](https://openrouter.ai/api/v1/models), el **13 de octubre de 2026**:

| Identificador exacto | Entrada USD / millón | Salida USD / millón |
| --- | ---: | ---: |
| `openai/gpt-5.4-mini` | 0,75 | 4,50 |
| `anthropic/claude-haiku-4.5` | 1,00 | 5,00 |
| `google/gemini-3.8-flash` | 0,75 | 3,75 |

El catálogo expresa `pricing.prompt` y `pricing.completion` en USD por token; se multiplicaron por un millón para rellenar `PRECIOS`.

```text
coste_usd = (tokens_entrada × precio_entrada + tokens_salida × precio_salida) / 1_000_000
```

Es una estimación con tarifas estándar, sin descuentos de caché ni cargos por herramientas. Un modelo sin precio verificado devuelve `None`. Estas tarifas corresponden a OpenRouter: no se atribuyen a la API nativa de Gemini, cuyo identificador pierde el prefijo `google/` en el constructor original.

## Validación real

Se hicieron **siete llamadas**: tres del bloque principal del script, una de Claude con la expresión del enunciado y tres con límite 20. Un comprobador temporal ejecutó el bloque `__main__` mediante `runpy` con el Python de `.venv`, capturó la salida y observó los campos de límite del cuerpo HTTP sin registrar cabeceras ni credenciales. No hubo errores de API ni fue necesario repetir llamadas.

El script respondió con los tres proveedores, sin mostrar «pendiente»:

| Proveedor | Segundos | Tokens entrada | Tokens salida |
| --- | ---: | ---: | ---: |
| OpenAI | 1,54 | 21 | 32 |
| Claude | 3,01 | 25 | 45 |
| Gemini | 5,10 | 12 | 430 |

Para reproducir esta comprobación —consume saldo—:

```powershell
.\.venv\Scripts\python.exe llm_client.py
```

La llamada del enunciado:

```python
LLM("claude").responder("Responde en una frase.", "¿Qué es un token?").coste_usd
```

devolvió **0,000235 USD**: 25 tokens de entrada y 42 de salida, en 1,650 s. El cálculo es `(25 × 1 + 42 × 5) / 1_000_000`; coincidió con el campo de coste que devolvió OpenRouter.

### max_tokens=20

Se usaron el mismo sistema y prompt de la llamada anterior. Los límites se comprobaron tanto en los argumentos del SDK como en el JSON enviado por HTTP.

| Proveedor / formato | Campo HTTP | Segundos | Entrada | Salida | Razonamiento reportado | Resultado |
| --- | --- | ---: | ---: | ---: | ---: | --- |
| OpenAI / Responses | `max_output_tokens: 20` | 1,249 | 21 | 20 | 0 | Texto truncado; estado `incomplete` |
| Claude / Messages | `max_tokens: 20` | 1,557 | 25 | 20 | 0 | Texto truncado; `stop_reason=max_tokens` |
| Gemini / Chat | `max_tokens: 20` | 2,222 | 12 | 16 | 16 | Sin texto visible; `finish_reason=length` |

Gemini devolvió `message.content=null`, `completion_tokens=16` y `completion_tokens_details.reasoning_tokens=16`. Los 16 tokens contabilizados fueron de razonamiento, sin respuesta textual visible. No se cambió el límite ni se reintentó para obtener una respuesta más favorable. Tras observarlo, se normalizó únicamente `None` a `""` para respetar el campo `texto: str`; esa normalización se comprobó sin red. No se recortaron, inventaron ni recalcularon los contadores de la API. En esta ejecución ninguno superó 20, aunque los contadores no equivalen a contar palabras ni solo texto visible.

## Comprobaciones sin red

`tests/test_llm_client.py` comprueba las cuatro ramas con clientes simulados: sistema y prompt, temperatura cero, límite 20, omisión de parámetros, valor 512 de Claude, concatenación de bloques, coste, modelos sin precio y texto ausente sin alterar tokens. Las pruebas conservan incluso un contador simulado superior al límite para detectar cualquier recorte artificial.

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Resultado: **4 pruebas correctas**, con subcasos para los cuatro formatos. Interactions nativo y Ollama se comprobaron sin red; las llamadas reales usaron los tres proveedores configurados, con Gemini por OpenRouter. No se afirma haber hecho una llamada real a Gemini nativo ni a Ollama.
